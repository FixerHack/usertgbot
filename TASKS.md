# usertgbot — робочий трекер

Оновлюється після кожної суттєвої зміни. Джерело правди про те, що вже
зроблено, що в процесі, і що заплановано — звіряйся з ним перед новою
роботою і після завершення задачі.

## ✅ Зроблено

- VPS-деплой (Hostinger, Docker Compose) — `/opt/usertgbot`, 4 сервіси + postgres
- i18n UK/RU/EN + ручний вибір мови (не покладаємось лише на Telegram language_code)
- Бан з адмін-панелі реально блокує бота (LangAndBlockMiddleware)
- `/connect`: динамічний прогрес-бар, кнопка "спробувати ще раз", ліміт часу на Telethon-з'єднання
- 8 перемикачів функцій у налаштуваннях (видалені/змінені окремо, `.me`/`.ban`/`.check`, фото/гс окремо)
- Ігноровані чати показують назву, не ID
- Анти-спам (RateLimitMiddleware) на management_bot і manager_bot
- Адмін-панель: кнопка "Видалити юзера" (+ виправлено delete-cascade баг у SQLAlchemy)
- Анти-видалення тепер ловить фото/голосові без підпису (раніше пропускало — `raw_text` порожній для медіа без caption)
- Анти-видалення розширено на весь контент, де це технічно можливо: фото/гс/відео + generic fallback (документи/GIF/стікери/аудіо) як `send_document`, у межах ліміту 8МБ; ЛОКАЦІЇ (звичайні/живі/venue) теж — координати, не файл, надсилаються назад через `send_location`; працює і в групах, і в особистих
- Знайдено й виправлено: "не відновлює нічого" виявилось не багом, а тим, що перемикачі `deleted`/`edited` були вимкнені в налаштуваннях тестового акаунта з попереднього тестування UI — увімкнув назад
- **Кеш анти-видалення тепер переживає рестарти** — раніше `RecentMessageCache` жив тільки в RAM (звичайний dict), і КОЖЕН рестарт userbot-worker (деплой/краш/перезавантаження) обнуляв усе, губилось "у польоті" все, що чекало на можливе видалення (підтверджено живими тестами під час цієї сесії). Тепер SQLite-файл на диску (`data/message_cache.sqlite3`, WAL-режим, окремий на весь проєкт, рядки розділені по `owner_user_id`) — живо перевірено: 3 записи лишились навіть після ЖОРСТКОГО вбивства процесу (`stop.bat`, без штатного закриття). `aiosqlite` перенесено з dev- у runtime-залежності. На VPS — новий volume `./data:/app/data` у `docker-compose.prod.yml`, щоб файл не губився при передеплої контейнера.
- Ціни: Standard тепер 50 грн (було 100), Pro — 150 грн (було 200); Premium далі "в розробці"
- Фікс кодування логів (cp1251 → utf-8 reconfigure у `shared/logging_conf.py`) — emoji в захопленому тексті більше не ронять рядок логу
- Тарифна картка тепер показує ціну в 3 валютах (₴ · $ · ⭐) замість лише USDT+⭐
- **3-колонковий вибір тривалості підписки**: після «Купити» — Місяць/3 місяці/Рік, кожен з ціною в USD+⭐; 1 та 3 місяці без знижки, рік ×10 замість ×12 (−17%, показано бейджем на кнопці)
- **Реферальні посилання**: адмін створює код (вкладка «🔗 Реферали»), deep-link `/start ref_<code>` атрибутує нового юзера один раз (не перезаписується), опційна знижка % застосовується при кожній його покупці; посилання саме по собі підписки не видає — лише лічить переходи і які тарифи в підсумку купили. Бейдж `🔗 <код>` у картці юзера в адмінці.
- **Видача Premium вручну з адмінки** — кнопка `+Premium` поруч з +Std/+Pro (grant_subscription і так не мав перевірки `available`, працює на існуючій логіці)
- Адмінка: автогенерація реферального посилання (юзернейм бота через `get_me()` при `/admin`, кнопка 📋 копіювати) + редагування % знижки для вже створеного коду
- Нова команда `.send N текст` (Pro-only) — надсилає N копій (1-100) тексту в поточний чат, з паузою ~1с між повідомленнями (захист від Telegram FloodWait); при спрацюванні обмеження зупиняється і пише скільки встигло надіслати
- Повідомлення після `/connect`: прибрали 👤/🆔/📱 (зайвий шум), а "запустіть менеджер-бота" тепер окремим повідомленням з кнопкою-посиланням — раніше губилось як хвостовий рядок і половина юзерів його не помічала. Підтверджено живим тестом.
- Фікс: знижка 100% раніше ламала оплату ("Помилка створення інвойсу" — Crypto Pay відхиляє інвойс на $0). Тепер якщо ефективна ціна ≤0, підписка активується напряму без звернення до платіжного шлюзу (Stars теж — там був floor у 50⭐, який реально стягував би гроші за "безкоштовний" тариф)
- `test_mono/` — прототип оплати на картку Monobank (довільні суми працюють; ізольовано, у .gitignore)
- `test_login/` — консольний діагностичний інструмент для тестування логіну напряму (ізольовано, у .gitignore)
- Git: усе розкладено по тематичних комітах

## 🔧 В процесі / відомі обмеження

- **Акаунт друга (і згодом власний тестовий) не отримує код логіну** —
  підтверджено: це поведінка Telegram на рівні акаунта (є активна сесія →
  код йде лише в чат "Telegram", без SMS/дзвінка), НЕ залежить від IP чи
  api_id/hash (перевірено з мобільного інтернету і новими кредами — той
  самий результат). Обійти кодом неможливо. Чекаємо, чи саморозв'яжеться
  з часом; якщо ні — писати в підтримку Telegram.
- `WatchConnectMiddleware` (management_bot/middlewares.py) — тимчасова
  діагностика для цього кейсу, залишена навмисно на майбутнє (за проханням)

## 💡 Обговорені ідеї, ще не реалізовані

- Черга/самообмеження на вихідні `send_code_request`, щоб не спровокувати
  обмеження з боку Telegram при великій кількості клієнтів одночасно —
  дешевий перший крок, якщо стане актуально
- Пул кількох `api_id`/проксі для розподілу навантаження — дорожче і
  складніше, відкласти до реальної потреби в масштабі
- `test_mono` фаза 2: фіксовані ціни тарифів + реальна інтеграція в
  `subscribe.py` як платіжний метод (поки тільки довільні суми для тесту)
- **Premium: пріоритетна черга кешу + диск-кеш до 500МБ на файл** (ідея
  користувача) — Standard/Pro лишаються на поточному RAM-кеші (8МБ, 2000
  повідомлень, без пріоритету), Premium мав би тримати медіа довше і
  дозволяти набагато важчі файли, записуючи їх у ТИМЧАСОВІ ФАЙЛИ НА ДИСК
  (не RAM — інакше 500МБ файли покладуть сервер по пам'яті). Це окрема
  архітектурна робота: lifecycle тимчасових файлів, безпека шляхів,
  контроль вільного місця, чистка. Не почато — Premium-тариф сам ще
  "в розробці" (не продається), тому опрацьовувати логіку черги під
  неіснуючий тариф зарано. Робити, коли Premium реально піде в роботу.
